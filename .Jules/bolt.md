## 2026-03-05 - DOM-less HTML Escaping and Regex Fast-Paths in Markdown Streaming
**Learning:** Using `document.createElement('div')` inside string utility functions like `escapeHtml()` creates DOM allocation overhead and forces DOM parser interactions during real-time streaming markdown parsing. Replacing DOM manipulation with pure string `.replace()` calls eliminates DOM churn. Additionally, stateful regexes (`/g` flag) tested line-by-line retain `lastIndex` across lines, causing false negatives. Fast-path string checks (e.g. `includes('<think')`) avoid running multi-line regexes on every streaming chunk.
**Action:** Always prefer pure string replace for HTML entity escaping in JS parsers, use non-global regexes for line-by-line testing, and add fast-path substring checks before running expensive multi-line regexes during streaming.
